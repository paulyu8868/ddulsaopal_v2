## 📈 매매법: 떨사오팔

이름 그대로 "떨어지면 사고, 오르면 판다" — 변동성이 큰 SOXL의 단기 평균회귀(mean reversion) 성향을 이용하는 분할매수 전략입니다.

- **매수 (LOC):** 종가가 전날 종가보다 낮거나 같으면, 전날 종가를 주문가로 LOC(Limit on Close) 매수를 넣습니다. 한 번에 모든 자금을 쓰지 않고 자금을 여러 회차로 나눠 매수일마다 한 회차씩만 소진합니다.
- **복리 재투자:** 매도로 회수된 자금은 남은 회차 수만큼 다시 나눠 재투자되어, 자금이 점점 불어나는 구조입니다.
- **매도 (수익 실현, LOC):** 각 매수 회차는 개별로 관리되며, 매수가 대비 일정 비율(왕복 수수료를 커버하는 수준) 이상 오르면 해당 회차만 매도합니다.
- **손절 (MOC):** 일정 기간 이상 보유한 회차는 더 오르길 기다리지 않고 시장가(MOC)로 정리합니다.

이 전략은 SOXL이 등락을 반복하는 횡보·하락 구간에서 강하지만, **지속적인 상승장에서는 매수 신호 자체가 잘 나오지 않아 시장 수익률을 따라가지 못하는 한계**가 있습니다. 반대로 가장 위험한 시나리오는 진입 시점이 아니라 **장기간 회복 없는 하락장**입니다.

## 🏗 구조

```
EventBridge Scheduler (뉴욕 시간 기준 정시, 서머타임 자동)
 ├─ morning  (개장 1분 후, 09:31 ET)  ─┐
 ├─ evening  (자정 직후, 00:30 ET)     ├→ Lambda ddulsa-trading-bot (서울 리전)
 └─ backfill (안전망, 02:30 ET)       ─┘    ① main clone → ② 태스크 실행 → ③ 결과 커밋·push
                                                   │
GitHub ── 코드·PR 리뷰·데이터 저장(레포 = DB) ←────┘
 └─ Actions: 이미지 배포(ECR→Lambda) · 차트 갱신(DB push 트리거) · 수동 백업 실행
실패 시: CloudWatch 경보 → SNS 이메일 알림
```

- **실행 환경:** 스케줄·실행은 AWS(서울 리전 Lambda + EventBridge), 코드·리뷰·데이터는 GitHub. 매매 코드는 이미지에 굽지 않고 실행 시마다 main을 clone하므로, `config.yaml`·전략 변경은 PR 머지만으로 다음 실행에 반영됩니다. 상세는 [aws/README.md](aws/README.md).
- **전략 실행:** `daily_run.py`가 거래일 판정·주문 계산·제출을 오케스트레이션하고, 실제 매수/매도 판단은 `backtest_today.py`의 시뮬레이션 로직이 매번 시작일부터 다시 계산합니다.
- **데이터 저장:** 실행 환경은 매번 새로 뜨는 휘발성이라, `data/trading.db`(가격 이력)와 보유 회차 정보를 **이 레포 자체를 DB처럼 사용**해 매일 자동 커밋합니다.
- **브로커 연동:** `kis_api.py`가 한국투자증권 Open API(OAuth 토큰, 해외주식 시세/주문/잔고)를 래핑합니다.
- **모드 분리:** `dry-run`/`live` 모드별로 로그·보유 회차 파일이 분리 저장되어, 실거래 전에 안전하게 동작을 확인할 수 있습니다.
- **차트:** DB가 갱신되면 GitHub Actions(`update_charts.yml`)가 README 정적 차트(`generate_chart.py`)와 인터랙티브 대시보드(`generate_interactive_chart.py`)를 자동 재생성합니다.

## 🔧 운영 이슈 & 해결 기록

> 실거래 운영 중 실제로 겪은 문제들. 같은 패턴의 재발 방지를 위해 기록한다.

| 시기 | 문제 | 원인 | 해결 |
|---|---|---|---|
| 이관 전 | 스케줄 실행이 전부 조용히 스킵됨 | 크론 문자열 변경 시 잡의 `if: github.event.schedule == '...'` 조건을 함께 안 바꿈 | 크론과 `if` 조건 동시 수정 원칙화 (이관 후엔 조건 자체를 제거) |
| 이관 전 | KIS가 주문을 `주문불가 시간`으로 거부 | LOC/MOC는 접수 가능 시간(대략 개장~마감 20분 전 ET)이 정해져 있음 | 제출 전 시간 윈도우 가드 추가 |
| 이관 전 | evening이 KST 자정 이후 조용히 실패 | 미국 날짜로 "오늘"의 종가를 조회해 데이터 없음 | 하루 빼고 최근 유효 거래일을 탐색하도록 수정 |
| 2026-06~07 | **크론 지연 +1~4시간, 실행 20% 실패, 7/1 주문 미제출** | GitHub Actions 크론은 best-effort + 미국 러너 IP → KIS API 접속 타임아웃 | **실행을 AWS Lambda(서울)+EventBridge로 이관** (PR #7~#10) — 뉴욕 기준 정시 실행, 국내 네트워크 경로, 실패 시 SNS 이메일 |
| 2026-07 이관 중 | Lambda 이미지 빌드 실패 | 최신 pillow가 베이스 OS(AL2, glibc 2.26)용 휠을 미제공 → 소스 빌드 시도 | 차트 전용 의존성(matplotlib/plotly)을 이미지에서 제외 (PR #9) |
| 2026-07-09 | 이관 첫날 7/8 종가 미수집 | evening의 `대상일 = 미국 오늘 − 1` 로직은 **ET 자정 이후 실행 전제**인데, 정시(KST 10:00 = ET 전날 21:00) 실행으로 하루 밀림. GH 크론 지연이 그동안 우연히 가려주던 버그 | evening/backfill 스케줄을 ET 자정 이후(00:30/02:30)로 고정 — 코드 무변경 |
| 2026-07-09 | 대시보드 수익률 왜곡(+13%에서 시작) | 로그의 포트폴리오 스냅샷은 기록 당시 config가 섞여 있어 config 변경 후 신뢰 불가 | 대시보드 v2: 주문 마커 = 실제 제출 기록, 평가액·수익률 = 현재 config로 시작일부터 재계산 (PR #11) |

교훈 한 줄씩:
- **지연이 버그를 가릴 수 있다.** evening 날짜 로직은 GH Actions의 만성 지연 덕에 "정상 동작"해 왔고, 정시 실행이 시작되자마자 깨졌다. 타이밍에 암묵적으로 의존하는 코드는 그 타이밍이 좋아져도 깨진다.
- **green 실행 ≠ 주문 제출.** 태스크 내부 오류는 로그만 남기고 정상 종료하므로, 실행 성공 표시만 믿지 말고 주문 이력을 확인할 것.
- **로그는 사실의 기록이지 장부가 아니다.** config가 바뀌면 과거 스냅샷은 현재 기준과 어긋난다. 일관된 수치가 필요하면 현재 config로 재계산한다.
